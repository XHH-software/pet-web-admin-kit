# 宠物服务预约平台 · 业务说明

> 本文档描述管理端的业务流程和功能模块，供后端开发理解业务上下文。

---

## 1. 平台概述

宠物服务预约平台是一个面向宠物服务门店（宠物美容、洗护等）的 SaaS 系统，分为：
- **客户端（小程序）**：客户注册、浏览服务、预约下单、支付、评价
- **管理端（本项目）**：门店员工日常运营管理

本管理端为**单店模型**，一个门店对应一个管理后台实例。

---

## 2. 角色与权限

| 角色 | 说明 |
|------|------|
| 店长 | 最高权限，可管理所有模块，包括门店设置和员工管理 |
| 美容师 | 接收预约、执行服务、查看自己的排班 |
| 助理 | 协助美容师，代客下单，查看预约 |

> 当前版本暂不实现细粒度权限控制，所有登录员工可访问全部功能。

## 3. 核心业务流程

### 3.1 预约全流程

```
客户下单 → 待支付(1) → 待服务(2) → 服务中(3) → 已完成(5) → 已评价(6)
                ↓              ↓
            已取消(4)      已取消(4)
```

**状态流转规则**：

| 当前状态 | 可执行操作 | 操作人 |
|----------|-----------|--------|
| 1 待支付 | 取消预约 | 客户/商家 |
| 2 待服务 | 核销到店、取消预约 | 商家 |
| 3 服务中 | 完成服务 | 商家 |
| 4 已取消 | 无 | — |
| 5 已完成 | 无（等待客户评价） | — |
| 6 已评价 | 无 | — |

**管理端操作入口**：预约管理列表页的操作列

### 3.2 代客下单流程

商家在管理端代替客户下单（适用于电话预约等场景）：

1. 进入预约日历页面
2. 点击空闲时段 → 弹出代客下单对话框
3. 选择/搜索客户 → 选择宠物 → 选择服务项目
4. 确认时间、技师 → 提交
5. 系统自动检查时段冲突

### 3.3 排班流程

1. 店长进入排班管理页面
2. 查看一周排班概览（周视图）
3. 点击空白单元格 → 设置上班时间/下班时间/状态
4. 或使用「批量排班」为多个员工设置相同时间段
5. 或使用「复制上周排班」快速创建新一周排班

### 3.4 服务项目管理

1. 先创建分类（洗护、美容、保健等）
2. 再创建服务项目，关联分类
3. 设置价格、时长、适用体型、每日上限
4. 可创建套餐，组合多个项目

## 4. 页面功能说明

### 4.1 工作台 `/dashboard`

**用途**：门店运营数据一览

**模块**：
- 四个指标卡：今日预约数、待服务数、今日营业额、技师出勤率
- 近 7 日趋势图：双 Y 轴（柱状=单量，折线=营业额）
- 技师排名 Top 5：按预约数/评分/营业额排序
- 今日预约简表：最近 5 条预约记录

### 4.2 预约管理 `/appointment`

**用途**：查看和管理所有预约

**功能**：
- 筛选：日期范围、状态、技师、关键词
- 列表：展示预约核心信息
- 操作：查看详情、核销到店、完成服务、取消预约
- 取消时需填写原因
- 详情抽屉：完整预约信息 + 服务明细 + 支付信息
- 顶部可切换到日历视图

### 4.3 预约日历 `/appointment/calendar`

**用途**：甘特图式查看每日预约分布

**功能**：
- 左侧技师列表，右侧时间轴（09:00-20:00）
- 已预约时段用色块标记
- 空闲时段可点击代客下单
- 当日显示当前时间指示线
- 支持日期前后切换

### 4.4 排班管理 `/schedule`

**用途**：管理技师每周排班

**功能**：
- 周视图：行=技师，列=7天
- 单元格显示排班时间和已约数量
- 点击编辑排班（上下班时间、状态）
- 批量排班：为多人设置相同时间段
- 复制上周排班：快速创建新一周

### 4.5 服务项目管理 `/service-item`

**用途**：管理门店提供的单项服务

**功能**：
- CRUD 操作
- 设置图片、名称、分类、价格、时长、适用体型、每日上限
- 启用/停用状态切换
- 筛选：名称、分类、状态

### 4.6 服务套餐管理 `/service-package`

**用途**：管理组合套餐

**功能**：
- CRUD 操作
- 基础信息：图片、名称、分类、售价、原价、每日上限
- 套餐明细：可添加/删除多个服务项目，设置数量
- 自动计算合计时长

### 4.7 分类管理 `/category`

**用途**：管理服务和套餐的分类

**功能**：
- Tab 切换：服务项目分类 / 服务套餐分类
- CRUD 操作
- 名称、排序、状态管理

### 4.8 宠物档案 `/pet`

**用途**：查看客户和宠物信息

**功能**：
- 左侧客户列表（搜索 + 卡片展示）
- 右侧宠物卡片网格
- 宠物详情抽屉（基本信息 + 历史预约）
- 疫苗过期红色标记
- **只读页面**：信息由客户在小程序维护

### 4.9 员工管理 `/staff`

**用途**：管理门店员工

**功能**：
- 新增/编辑员工
- 设置头像、姓名、手机号、职位、职级
- 设置擅长项目（多选）
- 新增时需设置密码，编辑时不显示密码字段
- 启用/停用状态切换
- 不支持删除（只能停用）

### 4.10 评价管理 `/review`

**用途**：查看客户评价并回复

**功能**：
- 列表展示：客户、宠物、技师、评分、内容、回复状态
- 回复评价（只能回复一次）
- 筛选：评分范围、日期范围、是否已回复

### 4.11 门店设置 `/shop`

**用途**：管理门店基本信息

**功能**：
- 设置门店名称、Logo、联系电话、地址
- 营业状态开关
- 营业时间设置（周一到周日，每天可设休息）

### 4.12 登录页 `/login`

**用途**：员工登录

**功能**：
- 账号密码登录
- 表单校验
- 登录后跳转工作台
- 退出登录清除 token

## 6. 关键业务规则

### 6.1 预约冲突检查

- 同一技师在同一时段只能接一个预约
- 检查逻辑：新预约的 [startTime, endTime] 与已有预约的时段不重叠
- 冲突时返回错误提示，前端展示

### 6.2 服务时长计算

- 单个项目：直接使用项目的 duration 字段
- 套餐：取套餐中所有项目的 duration × quantity 之和
- 预约的 endTime = startTime + 总时长

### 6.3 金额计算

- 单个项目：price × quantity
- 套餐：sellingPrice（套餐售价）
- 总金额：所有项目/套餐的金额之和

### 6.4 订单号生成

- 格式：`AP` + `YYYYMMDD` + 4位序号
- 示例：`AP202611050001`
- 每天序号从 0001 开始递增

### 6.5 疫苗过期判断

- 比较 `vaccineExpiryDate` 与当前日期
- 如果 `vaccineExpiryDate < today`，标记为「已过期」
- 前端用红色标签显示

### 6.6 排班复制逻辑

- 复制前一周同一天的排班到新一周
- 如果目标日期已有排班，则覆盖
- 复制时保留上下班时间，但 bookedCount 重置为 0

## 7. 前端技术要点

### 7.1 状态管理

- 使用 Pinia，仅管理用户登录状态
- token 存储在 localStorage
- 页面内状态使用 `ref` / `reactive`

### 7.2 请求封装

- axios 拦截器统一处理：
  - 请求头添加 token
  - 响应剥离外层 data
  - 401 自动跳转登录
  - 错误统一提示

### 7.3 枚举管理

- 所有状态码定义在 `src/constants/enums.js`
- 前端使用数字比较，不使用字符串
- StatusTag 组件统一渲染状态标签

### 7.4 组件复用

- PageHeader：页面标题 + 操作按钮
- FilterBar：筛选栏容器
- StatusTag：状态标签（支持多种字典）
- EmptyState：空数据展示
- ImageUpload：图片上传（支持粘贴）

## 8. 部署说明

### 8.1 开发环境

```bash
cd D:\pet-web-admin-kit
npm install
npm run dev
# 访问 http://localhost:8081
```

### 8.2 生产构建

```bash
npm run build
# 输出到 dist/ 目录
```

### 8.3 环境变量

| 变量 | 开发环境 | 生产环境 |
|------|---------|---------|
| VITE_API_BASE | /api | /api（由 Nginx 转发） |

### 8.4 Nginx 配置示例

```nginx
server {
    listen 80;
    server_name admin.example.com;

    location / {
        root /path/to/dist;
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://backend:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
